# 功能卡：弟子谱交互指令接入（一期）

## 功能信息

- 功能名：弟子谱交互指令接入（一期）
- 优先级：`P1`
- 目标版本：`2026-03-15 弟子交互接入`
- 关联系统：`DL-043`、`DL-082`、`DisciplePanel`、`DiscipleDirectiveRules`、`CombatSystem`、`EconomySystem`

## 目标与用户收益

- 目标：让弟子谱不再只是静态档案，而能把玩家对个体弟子的重点培养批注接入实际结算。
- 玩家可感知收益（10 分钟内）：在弟子谱里选中某名弟子后，可直接将其纳入 `外务候补` 或 `执事培养`，随后从弟子详情、探险日志与资源回流中看到反馈。

## 实现范围

- 包含：
  - `GameState` 新增弟子交互指令存档字段
  - 弟子谱新增 `常制观察 / 纳入外务 / 执事培养` 三档交互按钮
  - `外务候补` 接入 `CombatSystem`，影响历练战力与外务回流
  - `执事培养` 接入 `EconomySystem`，影响贡献回流
  - 弟子详情页显示当前交互批注与效果摘要
- 不包含：
  - 不做弟子实体化 AI
  - 不做正式执事任命系统
  - 不做逐人任务排班

## 实现拆解

1. 为弟子交互指令补最小可存档模型与规则层。
2. 在弟子谱右侧新增交互批注区与按钮事件。
3. 将批注接到主循环，由 `GameLoop -> systems` 承接状态写入与结算。
4. 回写系统规格、功能台账、开发列表与平衡记录。

## 验收标准（可测试）

- [ ] 弟子谱中选中弟子后，可下达 `常制观察 / 纳入外务 / 执事培养`。
- [ ] 交互批注能写入 `GameState` 并随 `Clone()/存档` 保持。
- [ ] `外务候补` 会影响探险战力 / 回流，且日志可读。
- [ ] `执事培养` 会影响贡献回流，且弟子谱可读到当前效果摘要。
- [ ] `dotnet build .\Finally.sln` 通过。

## 风险与回滚

- 风险：如果弟子批注只改 UI 而不进系统，会造成“看起来能点、实际上无作用”的假交互；如果加成过大，会稀释治宗中枢与峰脉协同的价值。
- 回滚方式：移除弟子谱交互按钮与 `DiscipleDirectiveRules` 的结算接入，保留弟子谱档案展示链与已完成的详情信息补强。
