# 功能卡：弟子谱交互指令接入（第二期：治宗落实联动）

## 功能信息

- 功能名：弟子谱交互指令接入（第二期：治宗落实联动）
- 优先级：`P1`
- 目标版本：`2026-03-15 弟子交互接入`
- 关联系统：`DL-082`、`DiscipleDirectiveRules`、`SectTaskRules`、`TaskPanel`、`EconomySystem`

## 目标与用户收益

- 目标：让 `执事培养` 不再只影响贡献回流，而是进一步进入治宗册的执行反馈与内务条目效率。
- 玩家可感知收益（10 分钟内）：在弟子谱里点定执事培养对象后，不只卷中有批注，治宗册中的庶务条目也会显示“执事培养补位 / 加持”，并对内务条目收益产生影响。

## 实现范围

- 包含：
  - 为 `执事培养` 增加“内务执行效率”修正
  - 将该修正接入 `SectTaskRules` 的执行摘要与条目详情
  - 将该修正接入 `EconomySystem` 的内务类条目收益
- 不包含：
  - 不做正式执事任命席位
  - 不做逐条任务分配到个人
  - 不做新 UI 面板

## 实现拆解

1. 扩展弟子交互规则，派生 `执事培养` 的内务执行效率修正。
2. 将修正写入治宗册摘要、庶务条目详情与执行文本。
3. 将修正接入内务类任务收益计算。
4. 回写文档与平衡记录。

## 验收标准（可测试）

- [ ] `执事培养` 会影响治宗册中的执行摘要或条目说明。
- [ ] 内务类任务收益会受 `执事培养` 的执行效率修正影响。
- [ ] 外务类条目不会错误吃到执事培养加成。
- [ ] `dotnet build .\Finally.sln` 通过。

## 风险与回滚

- 风险：如果把修正挂成全局乘区，可能让 `执事培养` 越权覆盖所有系统；如果文案不解释，会让玩家看不懂为什么治宗册突然变强。
- 回滚方式：保留一期 `贡献回流` 接入，仅撤回二期的 `治宗执行效率` 修正与对应文案。
