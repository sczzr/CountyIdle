# 功能卡：弟子谱交互指令接入（第三期：执事候选池自动补位）

## 功能信息

- 功能名：弟子谱交互指令接入（第三期：执事候选池自动补位）
- 优先级：`P1`
- 目标版本：`2026-03-15 弟子交互接入`
- 关联系统：`DL-082`、`DiscipleDirectiveRules`、`SectTaskRules`、`TaskPanel`

## 目标与用户收益

- 目标：让“执事培养”从抽象加成进一步演进为可解释的自动补位候选池。
- 玩家可感知收益（10 分钟内）：把弟子标记为执事培养后，治宗册能直接看到当前是哪位弟子在补哪条庶务，弟子页也能看到自己是否正在代行某条执事职责。

## 实现范围

- 包含：
  - 自动从执事培养名册中筛选候选弟子
  - 按当前治宗条目自动为内务类任务分配“执事补位”
  - 在治宗册条目与弟子页中展示当前补位对象与效果
- 不包含：
  - 不做玩家手动逐条任命
  - 不做正式执事官阶或席位系统

## 实现拆解

1. 构建执事候选池与任务自动匹配规则。
2. 为内务条目计算按人派生的补位效率修正。
3. 在治宗册与弟子谱中展示当前补位对象。
4. 回写文档与平衡记录。

## 验收标准（可测试）

- [ ] 治宗册内务条目可显示当前补位执事姓名。
- [ ] 弟子谱中被选中的执事培养对象可显示自己当前是否在代行某条庶务。
- [ ] 自动补位不会作用到纯外务条目。
- [ ] `dotnet build .\Finally.sln` 通过。

## 风险与回滚

- 风险：如果补位规则过黑箱，玩家会不知道为什么是某个弟子被选中；如果把外务条目也纳入，会混淆“执事培养”和“外务候补”的边界。
- 回滚方式：撤回候选池自动补位文本与任务级补位规则，仅保留二期的治宗执行效率加成。
