# CP-20260318：弟子修炼卷接入专精效果落地

## 提案信息

- 标题：弟子修炼卷接入专精效果落地
- 日期：2026-03-18
- 提案人：Codex
- 变更级别：`L2 机制`

## 改动背景

- 当前问题：DL-088 已经做出了专修分支与功法技艺专名，但这些专名仍容易被读成“更好看的标签”，玩家还不够容易判断它们是否真的落到了玩法结果上。
- 证据（数据/玩家反馈）：当前弟子谱 / 修炼卷已能看到专修分支与专名，下一步自然是让这层专名继续汇入个体表现，并在任务/差事/外务相关说明里显式回显。

## 改动内容

- 改什么：
  - 让专修分支映照出的专名继续落成轻量专精效用。
  - 专精效用直接并入弟子的派生个体表现，而不是新增永久基础属性字段。
  - 弟子谱 / 修炼卷显式展示“专精效用”摘要。
  - 任务详情、外务战报与差事结果说明继续回显这层专精效用。
- 不改什么：
  - 暂不新增新的持久化字段。
  - 暂不做独立技能树或玩家主动加点。
  - 暂不把专精效用做成大幅数值膨胀。
- 影响系统：
  - `DiscipleCultivationRules`
  - `DiscipleCultivationSettlementSystem`
  - `DiscipleDirectiveRules`
  - `DiscipleDirectiveSystem`
  - `SectTaskRules`
  - `CombatSystem`
  - `DisciplePanel`
  - `CultivationPanel`

## 预期结果

- 预期提升指标：
  - 玩家能直接看懂“这个专名现在实际带来了什么”。
  - 任务详情 / 外务战报 / 差事说明中的培养结果会更具体。
  - 专修分支不再只是说明层，而会继续落到弟子真实派生表现上。
- 可接受副作用：
  - 文案会更长。
  - 若专精效用加成过大，可能会稀释原有路数与差事相性平衡，因此必须保持轻量。

## 验证计划

- 验证方式：
  - `dotnet build .\Finally.sln`
  - 检查弟子谱 / 修炼卷是否显式显示专精效用
  - 检查任务详情 / 外务战报 / 指令反馈是否开始回显专精效用
  - 检查个体表现反馈是否已吸收专精效用
- 观察周期：单次开发验证先看 8-16 次时辰结算及若干条任务/外务结果
- 成功判定阈值：
  - 专精效用可读且可见
  - 不新增存档迁移成本
  - 不压过主火候与主路数本身

## 回滚条件

- 触发条件：
  - 专精效用文案过密，影响卷册与结果页阅读
  - 加成过强，破坏现有轻量成长平衡
  - 结果页与卷册对专精效用的口径不一致
- 回滚步骤：
  - 回退 `DiscipleCultivationRules` 中的专精效用合并逻辑
  - 回退 `DiscipleDirectiveRules` / `SectTaskRules` / `CombatSystem` 中的专精效用回显
  - 回退 `DisciplePanel` / `CultivationPanel` 中的专精效用展示
