# 变更提案：院域同地块多建筑落位

## 变更主题

- Topic：`multi-building-per-tile`
- 关联功能包：`DL-047` 天衍峰院域坊局与全格检视系统、`DL-090` 文明式营建卷
- 变更级别：`L2` 机制增强

## 改动前

- 文档规格已经把院域坊局定义为“同地块 `2~3` 个建筑槽位”。
- 运行版的 `TownBuildingPlacements` 与 `TryPlaceBuildingAnchor()` 仍会把同地块旧建筑删掉，实际效果退回到“`1` 地块 = `1` 建筑”。
- 玩家点中已有建筑锚点后，营建卷还会把该状态视为“不可继续建造”，进一步放大单格单建筑的限制。

## 改动后

- 同地块建筑落位按 `BuildSlotCount` 控制，而不再按“是否已有建筑”二值判断。
- 同地块可共存多种建筑，地图显影改为分位偏移，卷面摘要改为多建筑列表。
- 玩家点中已有建筑时，仍视为锁定该地块，可继续追加建造，直至槽位满额。

## 飞轮影响

- 产业涌现：同地块混编产务 / 治务 / 研修建筑更符合文明式城市建造节奏。
- 科技涌现：院域推荐用途不再只是静态说明，而能被玩家连续兑现为实际组合。
- 反哺宗门：营建卷与山门图的建造反馈更一致，减少“文档说能混编，运行版却只能单建”的认知落差。

## 验证指标

- 同格连续建造 `2` 次后，`TownBuildingPlacements` 中应保留 `2` 条同坐标不同建筑类型记录。
- 重新生成地图、读档或刷新视图后，该地块仍显示同格多建筑。
- 点中已有建筑锚点时，营建卷按钮与建造条目不应错误锁死。

## 风险与缓解

- 风险：同格多建筑会让锚点命中、深度排序与重建逻辑出现覆盖或闪烁。
- 缓解：
  - 用每格槽位偏移稳定绘制同格建筑；
  - 重建时按地块分组恢复，而不是每次恢复一条就清空整格；
  - 对 UI 使用统一的“槽位剩余”口径，避免某处说可建、某处说已满。
