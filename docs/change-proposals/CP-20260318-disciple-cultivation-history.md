# CP-20260318：弟子修炼卷接入履历回看

## 提案信息

- 标题：弟子修炼卷接入履历回看
- 日期：2026-03-18
- 提案人：Codex
- 变更级别：`L2 机制`

## 改动背景

- 当前问题：修炼卷已经支持聚合收益与长期火候，但玩家仍缺少“最近发生了什么”的回看层，难以从弟子角度理解培养轨迹。
- 证据（数据/玩家反馈）：DL-088 当前已经进入长期成长阶段，下一步自然收口项就是把主修切换与关键火候跃迁沉淀成可读履历。

## 改动内容

- 改什么：
  - 为每名弟子新增近时修炼履历存储。
  - 在修炼安排切换时写入一条履历。
  - 在关键火候跃迁时写入一条履历。
  - 弟子谱与修炼卷同步展示最近修炼记录。
- 不改什么：
  - 暂不做独立履历面板或完整时间轴。
  - 暂不把每次普通时辰收益都写成履历，避免刷屏。
  - 暂不接入更复杂的修炼分支树。
- 影响系统：
  - `GameState`
  - `DiscipleCultivationRules / System / SettlementSystem`
  - `DisciplePanel / CultivationPanel`

## 预期结果

- 预期提升指标：
  - 玩家能看懂“这名弟子最近修了什么、何时切换、何时长进”。
  - 修炼卷与弟子谱在叙述层更像“卷册”，不只剩状态数字。
  - 履历反馈保持轻量，不压过主日志链。
- 可接受副作用：
  - 履历文本会增加少量 UI 文本长度。
  - 当前只记录关键节点，不记录每次普通修炼细目。

## 验证计划

- 验证方式：
  - `dotnet build .\Finally.sln`
  - 切换某弟子的主修安排，确认履历新增一条
  - 连续观察至火候跨段，确认履历新增跃迁记录
  - 对比弟子谱与修炼卷的履历摘要是否一致
- 观察周期：单次开发验证先看 6-12 次时辰结算
- 成功判定阈值：
  - 履历记录可持久化且旧存档兼容
  - 同一弟子在两个界面看到的履历口径一致
  - 履历数量稳定收敛，不出现无限膨胀

## 回滚条件

- 触发条件：
  - 履历文本导致 UI 明显拥挤
  - 主修切换 / 跃迁写入逻辑出现重复刷记录
  - 存档兼容受损
- 回滚步骤：
  - 移除 `GameState` 的修炼履历字段
  - 回退修炼卷与弟子谱中的履历展示
  - 保留修炼安排、聚合收益与长期成长摘要
