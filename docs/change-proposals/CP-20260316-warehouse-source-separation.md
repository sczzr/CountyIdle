# 改动提案（Change Proposal）

## 提案信息

- 标题：仓储三源产出分层与入库流程
- 日期：2026-03-16
- 提案人：Codex
- 变更级别：`L2 机制`

## 改动背景

- 当前问题：
  - 经营产出、外务收获与手动制造的资源目前容易混入同一库存，玩家难以理解“资源来自哪条线”；
  - 外务战利品与手作成品缺少可见的入库动作，反馈不够直观。
- 证据（数据/玩家反馈）：
  - 需求提出“仓库系统应同时承载模拟经营产出、冒险收获、手动制造产出，并能清晰区分”。

## 改动内容

- 改什么：
  - 定义仓储三源分层：经营产出直接入宗门仓库；外务收获先入行囊；手动制造先入工坊成品；
  - 增加“入库动作”与仓储卷的三源摘要反馈；
  - 资源消耗只认宗门仓库，行囊/成品不参与自动消耗。
- 不改什么：
  - 不改变现有产出数值、材料层级与战斗结算算法；
  - 不重做历练地图与制造配方系统。
- 影响系统：
  - `GameState` 仓储字段
  - `CombatSystem` 外务结算
  - `IndustrySystem / EconomySystem` 经营产出
  - 仓储卷 UI 与入库交互

## 预期结果

- 预期提升指标：
  - 玩家能在一次仓储查看中理解“经营 / 外务 / 手作”的来源差异；
  - 外务战利品与手作成品有明确的入库反馈。
- 可接受副作用：
  - 需要多一次入库操作，短期内交互步骤略增。

## 验证计划

- 验证方式：
  - `dotnet build .\Finally.sln`
  - 手动检查：经营产出、外务收获、手作成品分别落入对应层，并可入库
- 观察周期：
  - 本轮开发后立即验证
- 成功判定阈值：
  - build 通过；
  - 三源摘要与入库动作可用；
  - 不影响小时结算与既有消耗逻辑。

## 回滚条件

- 触发条件：
  - 行囊/成品暂存导致资源无法被正确入库或仓储 UI 崩溃；
  - 旧存档出现兼容问题。
- 回滚步骤：
  - 产出直接回写宗门仓库；
  - 暂存层字段保留为空，UI 入口隐藏。
