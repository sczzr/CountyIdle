# CP-20260318：弟子修炼卷接入小时结算

## 提案信息

- 标题：弟子修炼卷接入小时结算
- 日期：2026-03-18
- 提案人：Codex
- 变更级别：`L2 机制`

## 改动背景

- 当前问题：修炼卷已支持按弟子登记技能修炼、功法打磨、技艺练习与打坐修炼，但仍停留在“状态记录”阶段，未对小时结算产生真实反馈。
- 证据（数据/玩家反馈）：当前 `docs/05_feature_inventory.md` 与 `docs/08_development_list.md` 都已将“尚未接入时辰结算与成长规则”列为下一步收口项。

## 改动内容

- 改什么：
  - 新增独立的弟子修炼小时结算系统，按修炼卷登记的弟子主修安排折算为实际收益。
  - `技能修炼` 产出少量传承研修与贡献点。
  - `功法打磨` 产出更高的传承研修。
  - `技艺练习` 产出少量工器与贡献点。
  - `打坐修炼` 提升少量民心，并对危兆提供轻微缓冲。
  - 修炼卷与弟子谱文案同步改为“当前已生效”口径。
- 不改什么：
  - 暂不做逐弟子属性永久成长。
  - 暂不改变弟子谱派生属性公式与名册生成逻辑。
  - 暂不新增新的长期资源或新存档表结构。
- 影响系统：
  - `GameLoop`
  - `DiscipleCultivationRules / System`
  - `Economy / Research / Population` 小时结算链路旁挂
  - `CultivationPanel / DisciplePanel`

## 预期结果

- 预期提升指标：
  - 修炼卷安排在 1-3 个时辰内出现可见反馈。
  - 传承研修增量保持温和，不绕开现有治理/职司主链。
  - 技艺练习与打坐修炼提供可感知但不过量的辅助回流。
- 可接受副作用：
  - 早期若集中安排功法打磨，突破节奏会略快于当前版本。
  - 文案需要更明确说明“当前为聚合折算，不是逐弟子手动修炼模拟”。

## 验证计划

- 验证方式：
  - `dotnet build .\Finally.sln`
  - 运行时观察修炼卷安排后 1-3 次小时结算日志
  - 对比安排前后 `Research / IndustryTools / Happiness / Threat` 的变化趋势
- 观察周期：单次开发验证先看连续 6 次小时结算
- 成功判定阈值：
  - 安排后能稳定产生日志与状态变化
  - 不出现负值、存档破坏或主循环中断
  - 单小时修炼增益不压过现有治理/产业主链

## 回滚条件

- 触发条件：
  - 修炼卷收益明显压过现有传承研修或产业主链
  - 存档读取出现兼容问题
  - 小时结算日志噪声过大或造成主要状态异常波动
- 回滚步骤：
  - 移除 `GameLoop` 中的修炼小时结算调用
  - 保留修炼卷 UI 与状态登记
  - 回退文案到“登记态”说明
