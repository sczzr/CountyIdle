# CP-20260318：弟子修炼卷接入长期成长

## 提案信息

- 标题：弟子修炼卷接入长期成长
- 日期：2026-03-18
- 提案人：Codex
- 变更级别：`L2 机制`

## 改动背景

- 当前问题：修炼卷已能在时辰结算中产生聚合收益，但玩家仍看不到“某名弟子在这条修炼路线上练到了哪一步”，缺少个体长期成长手感。
- 证据（数据/玩家反馈）：`docs/05_feature_inventory.md` 与 `docs/08_development_list.md` 当前都将“逐弟子长期成长、修炼履历回看与更细收益反馈”列为 DL-088 的下一步收口项。

## 改动内容

- 改什么：
  - 为四类修炼安排新增按弟子持久化的长期成长进度。
  - `技能修炼` 累积“根基磨砺”。
  - `功法打磨` 累积“功法火候”。
  - `技艺练习` 累积“技艺手感”。
  - `打坐修炼` 累积“静修积气”。
  - 弟子谱与修炼卷同步展示当前火候与累计摘要。
  - 时辰结算在跨过阶段门槛时追加简短成长日志。
- 不改什么：
  - 暂不把长期成长直接折算为弟子基础属性永久上涨。
  - 暂不新增独立履历面板或历史曲线图。
  - 暂不改变现有小时结算聚合收益口径。
- 影响系统：
  - `GameState`
  - `DiscipleCultivationRules / SettlementSystem`
  - `CultivationPanel / DisciplePanel`

## 预期结果

- 预期提升指标：
  - 玩家能在弟子谱中直接看到某弟子的修炼积累，不再只有“已登记某项安排”。
  - 修炼卷从“安排页”升级为“安排 + 成长回看”的轻量入口。
  - 时辰结算偶尔能给出阶段突破提示，强化长期培养反馈。
- 可接受副作用：
  - 当前长期成长仍属于阶段条而非复杂树状养成，表达会偏轻量。
  - 文本信息会略有增加，需要控制弟子谱细节区的可读性。

## 验证计划

- 验证方式：
  - `dotnet build .\Finally.sln`
  - 连续观察修炼卷安排下 6 次时辰结算，确认成长进度累计正常
  - 打开弟子谱与修炼卷，确认同一弟子的火候摘要一致
- 观察周期：单次开发验证先看连续 6 次时辰结算
- 成功判定阈值：
  - 长期成长字段能稳定写入并随存档持久化
  - 弟子谱 / 修炼卷口径一致
  - 新增成长反馈不压过现有聚合收益日志

## 回滚条件

- 触发条件：
  - 长期成长字段破坏旧存档兼容
  - 弟子谱文本过于拥挤导致可读性明显下降
  - 成长阈值设计导致日志噪声过大
- 回滚步骤：
  - 移除 `GameState` 中新增的长期成长字典字段
  - 回退修炼卷与弟子谱中的火候展示
  - 保留修炼安排与时辰结算聚合收益
